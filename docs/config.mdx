title: "Configuration"

Midway reads `midway.yaml` from the current working directory. Create a starting file with `midway init`, or choose another path with `-c` or `--config`:

```bash
midway --config ./config/midway.yaml run cargo build
```

## Configuration sections

The top-level `tokens` section contains optional credentials for notification services. Add only the services you use. Local desktop notifications do not require credentials.

| Key          | Fields                                                                       | Description                                    |
| ------------ | ---------------------------------------------------------------------------- | ---------------------------------------------- |
| `slack`      | Webhook URL                                                                  | Slack incoming webhook URL.                    |
| `discord`    | Webhook URL                                                                  | Discord webhook URL.                           |
| `telegram`   | `token`, `chat_id`                                                           | Telegram bot token and numeric chat ID.        |
| `ntfy`       | `server_url`, `topic`                                                        | Ntfy server URL and topic.                     |
| `email_smtp` | `smtp_server`, `smtp_port`, `username`, `password`, `from_email`, `to_email` | SMTP connection and sender/recipient settings. |

Credentials are stored in `midway.yaml` as plain text. Protect the file and avoid committing it to a public repository.

## Log files

Midway writes logs to rotating daily files in the operating system's cache directory:

- Linux: `$XDG_CACHE_HOME/midway` when `XDG_CACHE_HOME` is set; otherwise `~/.cache/midway`.
- macOS: `~/Library/Caches/midway`.
- Windows: `%LOCALAPPDATA%\midway`.

The current log file uses the `midway.log` prefix; older files are kept with date suffixes.

The `notification` and `command_notifications` sections are optional. If either whole section is omitted, Midway uses its defaults.

## Notification destinations

By default, `send_to` contains all notification methods: `Local`, `Slack`, `Ntfy`, `Discord`, `Telegram`, and `Email`. External services still need their credentials under `tokens` to deliver notifications.

If you define a `notification` section, set `send_to` explicitly. When the section is present but `send_to` is omitted, no destinations are selected. When `send_to` is set, only listed methods are eligible; configured methods left out are skipped. `pick_from` defaults to `All`, which selects every method in `send_to`.

For example, this configuration sends only to local desktop notifications and Slack:

```yaml
tokens: {}
notification:
	send_to:
		- Local
		- Slack
	pick_from: All
```

`pick_from` also accepts `Random`, `Half`, `OneThird`, and `Any` with a count to select one, about half, about one third, or up to the requested number of methods from the `send_to` list.

## Command notifications

If the `command_notifications` section is omitted, its defaults are:

| Field                                                 | Default | Description                                                                                            |
| ----------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------ |
| `notify_while_running`                                | `true`  | Enable periodic running notifications for commands started with `run` or `open`.                       |
| `minimum_runtime_for_completion_notification_seconds` | `10`    | Minimum command runtime, in seconds, before sending a completion notification.                         |
| `running_notification_interval_seconds`               | `15`    | Seconds between running notifications in both `run` and `open`; the first is sent after this interval. |
| `log_lines_to_include`                                | `5`     | Reserved for including command output in notifications; it does not currently affect behavior.         |

If you include `command_notifications`, provide all four fields:

```yaml
command_notifications:
  notify_while_running: true
  minimum_runtime_for_completion_notification_seconds: 10
  running_notification_interval_seconds: 15
  log_lines_to_include: 5
```

When `notify_while_running` is `true`, `midway run` and `midway open` send a running notification after each `running_notification_interval_seconds` interval while the command is still running. Both commands send a completion notification if the command runs for at least `minimum_runtime_for_completion_notification_seconds`. These settings are independent: a command can receive running notifications without qualifying for a completion notification, or vice versa. Existing configuration files using the `notify_after` section and its old field names are still accepted; new files should use the names shown above.
