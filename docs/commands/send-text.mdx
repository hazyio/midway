---
title: "Send a text notification"
description: "Send a notification immediately with custom text"
---

Use `midway send-text` to send a notification without running a command:

```bash
midway send-text --message "Deployment finished"
```

## Arguments

| Argument               | Required | Description                                                                          |
| ---------------------- | -------- | ------------------------------------------------------------------------------------ |
| `-m, --message <TEXT>` | Yes      | Text to send.                                                                        |
| `-b, --background`     | No       | Start the send in a detached process and return immediately.                         |
| `-c, --config <PATH>`  | No       | Read configuration from this path instead of `midway.yaml` in the current directory. |

Midway sends the text immediately through the notification methods selected by `notification.send_to` and `pick_from`; it does not apply the command-duration threshold used by `midway run`.

## Send in the background

Add `--background` (or `-b`) to start the send as a detached process:

```bash
midway send-text --background --message "Deployment finished"
```

Midway returns after starting the send. Pressing Ctrl+C or terminating the shell or hook that launched it will not stop the detached send. A system shutdown, explicit termination of the Midway process, or teardown of its execution environment can still interrupt it.

Background sends use `midway.yaml` from the current working directory. Make sure that file is available where the detached process starts.

Midway reads `midway.yaml` from the current working directory by default. Select another config file with `-c` or `--config`:

```bash
midway --config ./config/midway.yaml send-text --message "Deployment finished"
```

See [configuration](/config) to set notification destinations and [notification guides](/notifications/local) to configure a service.
